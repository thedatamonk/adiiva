# ADIIVA Voice AI Gateway

A high-concurrency, multi-user Voice AI Gateway built with Pipecat, FastAPI, and Redis. The gateway and pipeline workers run as separate processes, allowing independent scaling.

## Quick Start

```bash
git clone <repo-url>
cd adiiva
cp .env.example .env
# Fill in your API keys in .env
./start.sh
```

The script will auto-generate a `JWT_SECRET` and run `docker compose up --build`.

## Environment Variables

| Variable | Description |
|---|---|
| `DEEPGRAM_API_KEY` | Deepgram STT API key |
| `OPENAI_API_KEY` | OpenAI LLM API key |
| `CARTESIA_API_KEY` | Cartesia TTS API key |
| `JWT_SECRET` | JWT signing key (auto-generated by `start.sh`) |
| `REDIS_URL` | Redis connection URL (set automatically in Docker) |
| `MAX_CONCURRENT_SESSIONS` | Max concurrent sessions per user (default: 2) |
| `WORKER_BASE_PORT` | Starting port for worker processes (default: 9000) |
| `GATEWAY_HOST` | Hostname returned in worker URLs (default: localhost) |

## Architecture

- **Gateway** (`src/app.py`) — FastAPI server. Handles JWT auth, rate limiting, spawns worker processes, returns worker WebSocket URL. Does NOT run pipelines.
- **Worker** (`src/worker.py`) — Standalone Python process, one per session. Runs a Pipecat pipeline (Deepgram STT → OpenAI LLM → Cartesia TTS), heartbeats to Redis, cleans up on disconnect.
- **Client** (`client/`) — TypeScript/Vite app. Login form → `POST /connect` to gateway → WebSocket to worker.
- **Redis** — Worker registry, rate limiting, heartbeat TTLs, session metrics.

### Connection Flow

```
Client                    Gateway                              Redis                   Worker
  |                         |                                    |                       |
  |-- POST /token --------->|                                    |                       |
  |<-- { access_token } ----|                                    |                       |
  |                         |                                    |                       |
  |-- POST /connect (JWT) ->|                                    |                       |
  |                         |-- verify JWT (local HMAC)          |                       |
  |                         |-- check rate limit --------------->|                       |
  |                         |-- spawn worker process ------------|---------------------->|
  |                         |                                    |<-- register (port) ---|
  |                         |<-- read worker URL ----------------|                       |
  |<-- { worker_url } ------|                                    |                       |
  |                                                              |                       |
  |-- WebSocket connect ---------------------------------------------- ----------------->|
  |<====== audio streaming (direct, gateway not involved) ==============================>|
  |                                                              |<-- heartbeat ---------|
```

### Key Design Decisions

- **Direct handoff** — Gateway is not in the audio path. After auth and worker assignment, the client connects directly to the worker via WebSocket. Zero gateway overhead on audio streaming.
- **One pipeline per worker** — Each worker is an isolated process running one session. A crash affects only one user. Simple resource accounting.
- **TTL-based health** — Workers heartbeat to Redis every 10s (30s TTL). If a worker crashes, its Redis key expires automatically. No gateway babysitting.
- **In-memory port counter** — Gateway assigns ports starting from `WORKER_BASE_PORT` using a simple incrementing counter.

## API Endpoints

| Endpoint | Method | Description |
|---|---|---|
| `/token` | POST | Issue JWT token (query params: `user_id`, `password`) |
| `/connect` | POST | Auth + rate limit + spawn worker, returns `{ worker_url, session_id }` |
| `/health` | GET | Health check with active session count (from Redis) |
| `/metrics` | GET | Completed session metrics (from Redis) |

## Project Structure

```
src/
├── app.py              # Gateway — auth, rate limiting, worker spawning
├── worker.py           # Worker — standalone pipeline process
├── pipeline.py         # Pipecat pipeline (STT → LLM → TTS)
├── auth.py             # JWT creation and verification
├── rate_limiter.py     # Redis-based per-user concurrency control
├── user_store.py       # Demo user store with bcrypt
├── metrics.py          # Latency tracking and metrics collection
└── usage_tracker.py    # Per-session usage and cost estimation

client/
├── src/

├── test_gateway.py             # POST /connect endpoint tests
```

## Development

### Running locally

```bash
# Terminal 1: Start Redis
docker compose up -d redis

# Terminal 2: Start gateway
uv run uvicorn src.app:app --host 0.0.0.0 --port 8000

# Terminal 3: Start client
cd client && npm install && npm run dev
```

Open `http://localhost:5173`, login with a seed user, and click Connect.

When running locally, use `REDIS_URL=redis://localhost:6379` in your `.env`.

### Running tests

```bash
# Requires Redis running locally
uv run pytest tests/ -v
```
